## 1. 概述与设计支柱

### 1.1 现状诊断（为什么必须重做）

现版 `games/chinese/sheep_game.html` 名义上是「化学版羊了个羊」，实测机制为：

```
7×7 网格 → 每格 30% 概率留空 → 点任意格 → 该格元素进 7 格槽位
槽内出现 3 张相同 symbol → 消除 → 补空槽位
```

**缺失的是原版羊了个羊唯一的深度来源：多层堆叠 + 遮挡。** 后果有三：

1. **没有决策**。任何格子在任意时刻都合法可点，玩家的最优策略退化成「从左上角开始按顺序点」，直到槽位逼近 7 格才开始紧张。前 40 次点击是纯机械操作。
2. **没有信息不对称**。你看得见全部 49 格的内容，因此「记忆」和「取舍」这两条心理动线完全不存在——而这两条正是消除类玩法的乐趣主体。
3. **难度不可调**。唯一的难度旋钮是「空位概率」，调高只是让牌更少、局更短，而不是更烧脑。

另外两个实现缺陷必须记入：`checkMatches` 找到第一组三消即 `return`（一次点击最多消一组，无法连锁）；槽位已满时用 `alert()` 阻断（阻塞式弹窗，移动端体验差且无法本地化样式）。

### 1.2 三条设计支柱

#### 支柱一 ·「看不见的才要命」

> **每一张牌，都可能压着另外四张牌。**

玩家面对的永远是一个**部分可见**的信息场：被压住的牌你能看到它露出的边角，但点不动；你能推断它值不值得清，但必须先付出去清它上面那几张的代价。

**为什么这样更好玩**：这把「点牌」从**操作**变成**规划**。玩家的真实决策从"点哪张"升级成"先拆哪个角、先付出哪三张的槽位成本"。这是羊了个羊的全部张力来源——你永远在赌「上面这几张清完之后，露出来的值不值得」。

#### 支柱二 ·「同族，是一条后路」

> **三次同元素是正解；三次同族是玩家自己发现的捷径。**

槽位快满了怎么办？如果槽里正好躺着 F、Cl，而你看到一张 Br 露了头——**卤素族三连**成立，一把清空。这条路径不是系统给你的，是你**认出**来的。

**为什么这样更好玩**：它把化学知识从"贴在卡片上的装饰"变成了**可操作的游戏资源**。玩家为了活着，会主动记住「哪几个是卤素」「哪几个是稀有气体」——这是被动阅读永远达不到的记忆强度。同时它是**救命机制**而非主导策略（见 §4.5 的排除 `metal` 论证），因此不会破坏平衡。

#### 支柱三 ·「难度有边界，失败有解释」

> **你可以输，但永远不会输给「这局本来就没解」。**

生成器从构造上保证每局存在至少一条通关路径，并且**把这条路径保存下来**。玩家的每一次失败，都能归因到自己刚才点错的那一步。

**为什么这样更好玩**：羊了个羊原版最大的怨气是"感觉被系统阴了"。这里我们把「运气」彻底从失败原因里剔除，剩下的挫败感会转成"再试一次我就能过"的复玩动力——而且我们还有免费复活和三种道具兜底。

## 2. 核心循环

### 2.1 单次点击的完整状态流转

这是本作唯一的原子操作。所有其他系统都是它的上游（生成）或下游（反馈）。

```
[STATE 0] 玩家看到盘面
   │
   ├─ 触/点 落在某张牌 T 上
   │
   ▼
[STATE 1] 判定 T 是否被遮挡
   │   blocked(T) === true ?
   │
   ├── 是 ──► [1a] 抖动 T（CSS transform 抖动 180ms）
   │           短暂高亮「压住 T 的那几张牌」（CSS outline 脉冲 400ms）
   │           播放轻提示「这张被压住了」
   │           不消耗步数、不消耗道具、状态机回到 STATE 0
   │           ⚠ 这里不用 pointer-events:none 拦，见 §3.3 的论证
   │
   └── 否
          │
          ▼
[STATE 2] 前置校验：槽位是否已满？
          │   若 slot.length >= 7 → 不可能是「满」状态（满即已判负，见 §7.1）
          │
          ▼
[STATE 3] 提交移动（写快照 → 迁移数据）
          │   ① snapshot = 当前完整状态深拷贝（供撤销）
          │   ② 从盘面移除 T，alive.delete(T)
          │   ③ T 加入 slot 末尾（保持插入顺序，方便玩家读）
          │   ④ 重算 T 下方邻接牌的 blocked 状态（只重算 T 覆盖过的，≤4 张）
          │   ⑤ 播放 T「从盘面飞入槽位」的 CSS transition
          │
          ▼
[STATE 4] 消除判定循环（必须循环到不动点）
          │   while (true):
          │       ① 同元素三连：slot 内存在 symbol 出现 ≥3 次 → 清除该 symbol 的 3 张
          │       ② 同族三连：slot 内存在某族 ≥3 张「互不相同的 symbol」→ 清除这 3 张
          │       ③ 若本轮清除了任何东西 → chain++ , 结算得分 → continue
          │       ④ 否则 break
          │
          │   ⚠ 顺序铁律：② 必须考虑 ① 之后的槽位内容
          │   ⚠ 一次点击可能连出多组消除（如槽内同时有 A×3 与 B×3）→ 必须 while
          │
          ▼
[STATE 5] 连锁记账
          │   若 STATE 4 清除了 ≥1 组 → chain += 1（同族额外 +1）
          │   若 STATE 4 什么都没清 → chain = 0
          │   M = min(1 + 0.5 × (chain - 1), 3.5)        ← 倍率，见 §4.4
          │
          ▼
[STATE 6] 胜负判定（顺序不可交换）
          │   ① 若 slot.length >= 7 → 【失败：槽位溢出】(此时必定没消成)
          │   ② 若 alive.size === 0 且 slot.length === 0 → 【胜利】
          │   ③ 否则 → 继续
          │   ⚠ 必须先判定 ① 再判定 ②？不：二者互斥。但 ① 必须在消除之后判定，
          │      否则「第 7 张恰好凑成三消」会被误判为失败（见 §7.2 EDGE-01）
          │
          ▼
[STATE 7] 反馈渲染
          │   槽位球数 / 分数 / chain 视觉、元素卡弹层（同元素）或族徽弹层（同族）
          │   aria-live 播报「已消除 3 张 铁，槽位 2/7」
          │
          ▼
[STATE 0] 回到等待输入
```

### 2.2 循环节拍（心流设计）

| 阶段 | 单次点击耗时 | 玩家心理 | 设计手段 |
|---|---|---|---|
| 观察 | 0.3–1.5s | 「这三张里点哪个」 | 遮挡比例 67%（只 1/3 可点，见 §4.1） |
| 点击 | 0.1s | 期待 | 抬升 + 阴影加重的 hover/active 反馈 |
| 飞入 | 0.22s | 满足 | `transform` transition，落地卡入槽位有 8% 回弹 |
| 消除 | 0.35s | 爽 | 三张同时放大 1.15 → 淡出 + 一圈 CSS 扩散光环 |
| 揭示 | 0.4s | 学习 | 元素卡 / 族徽弹层，可点「看详情」跳转元素页 |
| 喘息 | 0.6s | 紧张回落 | 揭示牌面下方新暴露的可点牌，用**描边亮起 + 族色辉光恢复**做「点亮」提示（不用 `filter: brightness`，与本节遮挡态同理由） |

**目标：一局（24 张牌 / 8 组三消）净操作时长 90–150 秒。**

**关键依赖边**：

| 依赖 | 理由 | 若违反的后果 |
|---|---|---|
| S4 必须消费 S3 | 生成器需要「有效移除序」，而移除序由遮挡关系定义 | 无法保证有解，只能靠运气重试 |
| S7 必须包裹 S5 | 撤销要能恢复「被消除的牌」，必须快照整个槽位+盘面 | 撤销后分数/连锁对不上，产生刷分漏洞 |
| S13 必须被 S9–S12 依赖，而非反向 | 所有文案通过 `t(key)` 取，不得硬编码 | 中英两套文件逻辑分叉，维护成本翻倍 |
| S9 不得依赖 S2 之外的坐标来源 | 坐标必须一次性从 S2 求出并写进 CSS 变量 | 窗口 resize 时重新计算易出现层错位 |

### 3.2 逐系统规格（八节格式，精要版）

> 完整八节格式已在 §3.1 依赖表 + 各系统条目内覆盖：概述 / 机制 / 数据 / 公式 / 边缘情况 / UI 接口 / 依赖 / 验收标准。

#### S0 数据适配层

- **概述**：把 118 条元素数据洗成「关卡可用的符号池」。
- **数据**：`{ name, symbol, atomicNumber, category, link }`，来自 `elements-zh.js` / `elements-en.js`（全局 `const elements`）。
- **机制**：按关卡声明的 `symbols[]` 取子集，**不随机抽**——关卡符号池在 §5 里逐关写死，保证教学顺序与族匹配可达性。
- **公式**：`symbolOf(tile) = pool[ hash(tile.id + seed) % pool.length ]`（生成器阶段决定，见 S4）。
- **边缘情况**：`elements-zh.js` 与 `elements-en.js` 的 `symbol` / `atomicNumber` / `category` 完全一致，仅 `name` 与 `link` 不同 → 因此**所有逻辑索引必须用 `symbol`，绝不能用数组下标**（两文件顺序虽同，但下标耦合脆弱）。
- **UI 接口**：盘面瓦片为**纯 CSS 绘制**（族色填充 + 符号 + 序号），**不使用图片**；`photo/elements/{ZZZ}_{Sym}.png`（118 张全存在）仅供 S-03/S-04/S-06 弹层。理由见 §8.1.1。
- **依赖**：无。**验收**：任一关卡声明的 symbol 都能在数据表中查到，缺一个即抛错并回退到内置最小池。

#### S1 关卡配置表

- **概述**：六关的静态常量表（见 §5）。
- **数据**：`{ id, layers:[{off,rows[]}], nd, symbols[], props:{undo,eject,shuffle} }`。
- **验收**：`Σ(每层牌数) % 3 === 0`（否则无法全部消完）；启动时断言。

#### S2 几何构建器

- **概述**：把「层 + 每层每行的牌数」展开成带整数坐标的牌列表。
- **数据**：坐标单位是**半张牌的边长**（half-unit，记作 `hu`）。一张牌占 `2×2 hu`。
- **公式**（核心，务必按此实现）：

```
对第 li 层（li 从 0 开始，0 = 最底层）:
  maxN = max(rows)                                  // 该层最宽一行
  for ri, n in rows:
     gy = off + 2 × ri
     gx = off + (maxN − n) + 2 × j      j = 0 .. n−1
  像素坐标:
     left   = gx × --tile / 2
     top    = gy × --tile / 2
     width  = --tile
     height = --tile
  z-index  = layer × 100 + gy
```

- **为什么用半格**：`off` 每层 +1 就得到「上层每张牌正好落在下层四张牌中间」的经典错位堆叠（视觉上是真正的金字塔）；`off = 0` 则完全重叠对齐，视觉上是一摞牌。这是**唯一**的轮廓控制旋钮。
- **边缘情况**：
  - EDGE-G1 `rows` 里有 0 → 视为该行不存在，直接跳过（不要生成 0 张的空行，会白白撑高 `gy`）。
  - EDGE-G2 不同层的 `maxN` 不同 → **居中是以各自 `maxN` 为基准的**，因此整体呈金字塔收敛，不会左右歪。
  - EDGE-G3 同一层内两张牌 Δgx=2 时**只相邻不重叠**（见 §3.3 判定式用 `< 2` 而非 `<= 2`），因此同层不可能互相遮挡。
- **验收**：任取一关，`Σgx` 与 `Σgy` 的极值算出的盘面宽高 ≤ `(9, 8)` 个 tile 单位（375px 下每 tile ≥ 44px 的硬约束，见 §4.6）。

#### S3 遮挡引擎（本作技术核心）

- **概述**：唯一负责回答「这张牌现在能不能点」的模块。
- **机制**：遮挡 = **矩形相交**。确认采用矩形相交，但**必须离散化为整数运算**，不做浮点包围盒比较。
- **判定式**（这就是全部）：

```
covers(A, B)  ⟺  A.layer > B.layer  ∧  |A.gx − B.gx| < 2  ∧  |A.gy − B.gy| < 2
blocked(B)    ⟺  ∃ A ∈ alive : covers(A, B)
```

**为什么这个式子是对的**：两张牌各自占 `2×2 hu`。两张同尺寸轴对齐矩形的 x 方向有重叠 ⟺ 中心间距 < 边长 ⟺ `|Δgx| < 2`（`hu` 单位下边长 = 2）。y 同理。因此「两轴都重叠」= 矩形真交叠。`A.layer > B.layer` 保证只有上压下的单向关系。全部是整数比较，无浮点误差，无 `getBoundingClientRect()` 依赖——**因此可以在生成阶段（未渲染时）直接算，这是 S4 能工作的前提**。

- **增量重算**（性能与正确性）：
  ```
  当 alive 删除 T 后：
    for B in alive where covers(T 曾覆盖 B 的候选集):
        B.blocked = ∃A∈alive: covers(A,B)
  ```
  候选集只需检查 `|T.gx−B.gx|<2 ∧ |T.gy−B.gy|<2` 的牌（≤4 张）。**不要全量重扫**（45 张牌全量是 45²=2025 次/点击，虽然能跑但没必要）。

- **边缘情况**：
  - EDGE-O1 **被遮挡的牌必须仍然可见**。它是「下一步的诱饵」，隐藏了就毁掉支柱一。只做降亮度/去阴影，不做 `display:none`。
  - EDGE-O2 **被遮挡的牌必须仍然可被点中**（不接受 `pointer-events:none`），论点见 §3.3。
  - EDGE-O3 一张牌可能被**多张**上层牌同时遮挡 → `blocked` 是布尔，但「压住它的牌集合」要存下来，用于抖动时高亮。数据结构：`blockersOf: Map<tileId, tileId[]>`。
  - EDGE-O4 洗牌（S8）不改变几何，只改变 `symbol` → **遮挡关系完全不变，不需要重算**。

- **验收**：随机生成 100 局，断言「任一时刻 `alive` 中至少有一张 `!blocked`」（数学上必然成立：`layer` 最大的活牌不可能被遮挡）。此断言失败 = 存在悬浮 bug。

#### S4 牌面生成器（保证有解）

- **概述**：决定每张牌是什么元素，并**证明**该盘面可通关。
- **机制（三选一，选方案 C）**：

| 方案 | 做法 | 实测结果 | 结论 |
|---|---|---|---|
| A 纯随机 | 均匀随机发牌 | 大量无解局 | ❌ 违背支柱三 |
| B 按移除序分块发牌 | 取一条有效移除序，切成 B=3/6/9 的连续块，每块内含整组三张 | **100% 有解，但人类胜率也 100%**（含随机乱点的 AI 都 100%） | ❌ 过度约束，玩起来无脑 |
| **C 随机发牌 + 有界 DFS 验证 + 失败重掷** | 均匀发牌 → 有限节点预算的 DFS 找一条解 → 找到即采纳并**保存该解路径**；找不到就重掷 | **首掷成功率 ≈ 1.0**（实测 tries=1.0，见附录 A），人类胜率随 `nd` 从 100% 平滑降到 20% | ✅ 采用 |

  > 方案 B 被否决的理由值得记下：**「构造性保证有解」会强制三张同元素牌在移除序里彼此邻近**，等于告诉玩家「先露出来的三张就是一组」，游戏退化成按顺序点。这是本次设计最重要的一次试错结论。

- **算法（S4 定稿）**：
  ```
  generate(geometry, nd, seed):
    for attempt in 1..40:
        multiset = 对 i in 0..(nTiles/3 - 1): sym = pool[i % nd]，push 3 份
        shuffle(multiset, rng(seed + attempt))
        把 multiset 顺序映射到 geometry 的牌上（顺序无所谓，因为 DFS 会重排）
        r = solveDFS(board, slotMax=7, nodeBudget=8000, heuristic)
        if r.ok: return { assignment, witnessPath: r.path }   // 同时拿到提示道具的数据源
        if attempt % 10 == 0: nd = max(3, nd − 1)             // 温和降级，保证终止
    return generate(..., nd=3, ...)                            // 兜底：nd=3 几乎必然 1 次通过
  ```
- **DFS 启发式排序**（决定节点预算够不够用）：
  ```
  rank(tile) = 3  若 slot 内已有 2 张同 symbol  → 立即三消
             = 2  若 slot 内已有 1 张同 symbol  → 凑对
             = 0  其它
  候选按 rank 降序，同 rank 内随机打乱
  ```
- **关键不变量**：`nTiles % 3 === 0` 且每种 symbol 出现次数是 3 的倍数 → **全局一定能消完**（这是必要条件；DFS 检查的是「在 7 格槽位限制下是否还能消完」，即充分条件）。
- **数据**：`witnessPath` 是 `tileId[]`，即「按此顺序点必通关」。它有两个用处：① 证明有解；② **「提示」道具直接读它**。
- **边缘情况**：
  - EDGE-D1 `witnessPath` 会因玩家偏离而失效 → 提示道具必须**从当前状态重跑 DFS**（中局状态牌少，搜索空间更小，8000 节点绰绰有余），不能直接读初始路径。
  - EDGE-D2 重掷 40 次全失败（理论上不会，但要防死循环）→ 降 `nd` 兜底。
  - EDGE-D3 同一 `nd` 下，**symbol 的重复次数**可能不等（如 15 个三连分给 8 个 symbol → 2,2,2,2,2,2,2,1）→ 这是合法的，不要强行均分。
- **验收**：连跑 500 局，`generate()` 全部返回非空，平均 attempt ≤ 2，单次生成耗时 < 50ms（45 张牌）。

#### S5 槽位与匹配引擎

- **概述**：7 格槽位 + 两套匹配规则。
- **数据**：`slot: symbolId[]`（有序，按点击先后追加）。
- **机制**：见 §4.5 的匹配规则详述。
- **公式**：
  ```
  同元素三连成立  ⟺  ∃ s : count(slot, s) >= 3
  同族三连成立    ⟺  ∃ c ∈ FAMILIES_EXACTLY_6 :
                        |{ distinct s ∈ slot : category(s) === c }| >= 3
  清除时：优先取槽内最靠前的 3 张匹配牌（保持剩余顺序）
  ```
- **边缘情况**：
  - EDGE-M1 **两种匹配同时成立** → 先结算同元素（保留同族的可能性给下一轮，让玩家多赚一组）。
  - EDGE-M2 槽内 4 张同 symbol（理论上不该出现，但因撤销/暂存可能出现）→ 只清 3 张，留 1 张。
  - EDGE-M3 同族三连时槽内有 **4 张同族不同 symbol** → 清最靠前的 3 张。
  - EDGE-M4 槽内同族有 2 张 + 1 张同 symbol 的第 3 张 → 同元素先在 ① 命中，不会走到同族分支。
- **验收**：单元测试覆盖 M1–M4 四个构造用例。

#### S6 计分与连锁

见 §4.4。**验收**：构造「连消 3 组」的盘面，断言最终分 = 100×1.0 + 100×1.5 + 100×2.0 = 450。

#### S7 快照与撤销

- **概述**：撤销不做「反向推导」，做**全量快照回滚**。
- **机制**：
  ```
  snapshot = {
    alive: tileId[],          // 盘面剩余
    slot: symbolId[],         // 槽位内容（含顺序）
    bench: symbolId[],        // 暂存区
    score, chain, moves,
    rngState,                 // 保证撤销后重抽一致
  }
  ```
- **为什么快照而不是反向操作**：撤销一步可能撤销「一张牌入槽 + 一组三消 + 连锁倍率 + 族徽弹层」四件事。反向推导的分支组合极易出 bug；快照 45 个 id + 7 个 symbol，深拷贝成本可忽略（< 1KB）。
- **边缘情况**：
  - EDGE-U1 连续撤销 → 快照栈用一个数组，撤销即 `pop()`，最多存 20 层（一次撤销道具只用 1 层，但为撤销「撤销」的语义简单化，只保留可用道具次数）。
  - EDGE-U2 撤销不能撤销「已消耗的道具」→ 道具使用本身**不写快照**。
  - EDGE-U3 撤销后重放必须一致 → 快照里必须含 `rngState`（若有随机，例如洗牌）。
- **验收**：随机跑 200 步，每步后撤销一次，断言状态与上一步完全一致（深比较）。

#### S8 道具系统

见 §4.7。**验收**：三个道具各自在「无可用次数」时按钮置灰且不可聚焦。

#### S9/S10 渲染与输入

见 §3.3 与 §6。

### 3.3 「只有最上层可点」的纯 CSS + DOM 表达 —— 结论与论证

> 这是 engineering-lead 最需要的确定性答案。**结论与直觉相反，请注意。**

#### 三个候选方案

| 方案 | 做法 | 判定 |
|---|---|---|
| ① 纯 CSS `pointer-events` + `z-index` | 遮挡牌设 `pointer-events:none`，靠浏览器原生命中测试让点击穿透到上层牌 | ⚠️ 半对，有致命坑 |
| ② CSS `:has()` / 兄弟选择器推遮挡 | 用选择器表达「我上面有牌」 | ❌ 不可行 |
| ③ **JS 预计算 `blocked` 属性 + CSS 表达视觉 + JS 处理响应** | 生成期算好遮挡图，写入 `data-blocked` | ✅ **采用** |

**方案②不可行的原因**：CSS 选择器只能沿 DOM 树匹配，无法表达「两个绝对定位盒子的几何交叠」。`:has()` 能表达祖先/兄弟关系，但遮挡是**纯几何**关系，与 DOM 结构无关。必须放弃。

**方案①的致命坑**（这也是我要修正任务书假设的地方）：

`pointer-events: none` 会让**点击穿透到下层**。考虑：牌 B（layer 0）被牌 A（layer 1）部分遮挡。

- 点击 A 覆盖 B 的区域 → 浏览器命中 A → 正确。
- 点击 B **没被 A 覆盖的露出部分** → B 设了 `pointer-events:none` → 点击继续向下穿过 → 落到 `.sg-board` 容器 → **什么都不会发生，且没有任何反馈**。

玩家看到一张明明看得见、点下去却「死掉」的牌。这是明确的 UX 缺陷，而且在触屏上会被放大成"这游戏卡了"。

#### 采用方案的机制

浏览器原生的 z-index 命中测试**本来就已经解决了「谁接收点击」**：同一点上，`z-index` 最高的元素先收到事件。因为：

- **同层牌永不重叠**（Δgx = 2 时不构成重叠，见 S3 判定式）→ 同层无歧义；
- **跨层牌 z-index = `layer×100 + gy`** → 上层恒高于下层；
- 因此「点在 A 与 B 的重叠区」必然命中 A，「点在 B 的独有露出区」必然命中 B。

**这就是我们想要的语义**——不需要任何技巧。所以：

```
data-blocked 决定「视觉」，不决定「命中」
命中由浏览器按 z-index 天然完成
点击处理器根据 data-blocked 决定「响应」
```

**判定伪代码**（不含实现代码，只给逻辑）：

```
onTileTap(tileId):
    if gameState !== PLAYING:            return
    if isAnimating(tileId):              return          // 防连点
    if blocked.get(tileId):                              // ← 关键分支
        playFeedback('shake', tileId)
        highlightTiles(blockersOf.get(tileId))           // 告诉玩家「是这几张压着」
        announce('tile_blocked')                         // a11y 播报
        return                                           // 不消耗步数 / 道具 / 槽位
    commitMove(tileId)                                   // 进入 §2.1 STATE 3
```

**CSS 角色划分**（只做视觉，不做逻辑）：

#### 必须写 `isolation: isolate`（否则瓦片会钻进导航栏底下）

`z-index = layer×100 + gy` 在 3 层 × maxGy≈6 时最高约 **712**，已经闯进模态框（500+）的层级区间。同时 `styles.css` 里 `.navbar` 是 `z-index: 100`——**不隔离的话滚动手牌堆会浮到导航栏之上**（这是现版 `sheep_game.html` 的既存隐患）。

解法：`.sg-board { isolation: isolate }` 让牌堆内部自成层叠上下文，内部 z-index 与外部完全隔离。内部重排：

| 元素 | z-index |
|---|---|
| 瓦片 | `layer × 100 + gy`（不变） |
| 选中态 | `1000` |
| 飞行克隆 | `1100` |
| 消除爆裂 | `1200` |

模态框在 `.sg-board` 之外，用原有 z-index 即可，不会冲突。

#### ⛔ 不要用 `filter: brightness()/saturate()` 做遮挡态（已被实测否决）

早前版本给过一版基线 `filter: brightness(.62) saturate(.7)`，**必须废弃**。原因是硬的：

1. **`filter` 会把符号文字一起压暗**，导致对比度崩到不可读。实测 9 族中有 4 族跌破 WCAG AA 的 4.5：`metalloid` 5.36 → **3.72**、`metal-d` 5.90 → **3.96**、`alkaline-earth` 7.08 → **4.42**、`nonmetal` → **1.23**（最差：浅底 + 深字的牌被 filter 一起压暗，明暗两端同时变暗，对比度直接崩塌）。
2. **`::before` 伪元素同样会压暗文字**——因为定位伪元素在绘制顺序上高于 inline content。只有 `background-image` 层永远在 content 之下。**这是 filter 方案与 `::before` 方案共同的坑。**
3. 改用「背景图层」方案后，9 族对比度全部 ≥ 9.46，且零 `filter`、走合成器、无掉帧风险。

#### 「在下面」这个信号靠什么传达（实测通道强度排序）

| 通道 | 可点 → 遮挡的变化 | 强度 |
|---|---|---|
| **描边**（族色 .92 → .26） | 描边↔牌桌对比度 5.05–9.59 → 1.52–1.95 | **Δ 3.5–7.6（最强）** |
| **族色辉光**（消失） | 有辉光 → 无辉光 | 强 |
| 填充压暗 / 洗白 | 深色族 ΔL 最高仅 0.021 | 弱（仅辅助） |
| 饱和度 | 降幅最低 0.025 | 弱（仅辅助） |

> **结论：明度和饱和度在数学上扛不起"在下面"这个信号**（`metal-f #10208e` 本身 L≈0.02 已近黑，`metalloid` 本身 S 只有 0.361）。**主力是描边塌陷 + 辉光消失。** 实现时如果想让遮挡态更明显，优先加深描边差，不要加暗填充。

#### 浅底族必须「洗白」而非「压暗」

`data-pol` 按底色明度分档：深底族用深色 scrim 压暗，**浅底族（如 `nonmetal` #ffeaa7）必须用浅色 scrim 洗白**——若同样压暗，深色文字对比度会从 4.5+ 掉到 **3.38**，直接不可读。这就是 `data-pol="dark|light"` 存在的原因，实现时务必按族填充色明度正确分档。

> 引入逐 symbol 明度档（下一小节 R18）后，`data-pol` 仍**逐 symbol 写**（与 `data-tier` 同一赋值函数产出），但 9 族 × 4 档全表实测**没有任何一档跨越极性**——最险的是 `metal-d` T2 对白字 4.86，仍在 4.5 之上；浅底族越往高档越亮、对比度只升不降。所以 `data-pol` 的取值**恒等于族极性**，逐 symbol 写只是为了不让两条通路以后走岔。

#### 卡面信息分档（`--face = var(--tile) − 4px`）

**分类色条砍掉。** 因为瓦片填充色本身就是分类色，再加一条 4px 色条是重复占空间——在 51px 的 face 上会吃掉 8% 高度却不传递任何新信息。

**卡面基准已从 44px 上移到 55px**（art-director 本轮修订）：牌堆最多只有 4 行（§4.6），`--tile` 的实际取值域是 **55–72px**，44px 只是 320px 极端屏的产物，不该再当设计基准。分档门槛随之上移：

| `--tile` | `--face`（= tile−4） | 符号（0.42×face） | 原子序数（0.20×face） | 元素名 |
|---|---|---|---|---|
| < 55px | < 51px | **显示** 19.0–21.4px | 隐藏 | 隐藏 |
| 55–64px | 51–60px | **显示** 21.4–25.2px | 显示 10.2–12.0px | 隐藏 |
| ≥ 65px | ≥ 61px | 显示 **25.6px 起** | 显示 12.2px 起 | 显示 10.7px 起 |

落到本作六关（375px 基准）：

| 关卡 | `--tile` | 卡面内容 |
|---|---|---|
| L1 / L2 | 72px | 符号 + 序号 + **名称** |
| L3 / L5 | 65px | 符号 + 序号 + **名称** |
| L4 / L6 | 54.5 → **55px** | 符号 + 序号（无名称） |
| （320px 极端）L4 / L6 | 45px | **仅符号** |

**匹配可读性不受影响**：同元素三消靠符号（19px 起，已足够辨识），同族三消靠**填充色相**（9 族色差 + 明度档 + 纹样三重编码）。原子序数是"非必要辅助信息"，在 55px 以下被牺牲是正确取舍——**不要为它牺牲符号大小**。

#### 每个关卡实际只有 2–3 种填充色（问题已由 R18 明度档解决）

因为填充色承载的是**族**、而玩家主要靠**符号**配对，所以「唯一填充色数」远少于 `nd`：

| 关卡 | `nd` | 唯一填充色数 | 配色分布 | 备注 |
|---|---:|---:|---|---|
| L1 | 3 | **2** | `metal-d`×2 + `nonmetal`×1 | Fe/Cu 同色 |
| L2 | 4 | **2** | `metal-d`×3 + `metal-p`×1 | **Fe/Cu/Zn 三张同色** |
| L3 | 5 | 3 | halogen×2 + alkali×2 + `metal-d`×1 | |
| L4 | 6 | 3 | halogen×2 + alkali×2 + `metal-d`×2 | |
| L5 | 6 | **2** | halogen×4 + alkali×2 | **F/Cl/Br/I 四张同色** |
| L6 | 7 | 3 | halogen×4 + noble×2 + `metal-p`×1 | F/Cl/Br/I 四张同色 |

**这未必是缺陷**——同色确实正确地传达了「这 4 张属于同一族、可以族三连」，是有信息量的。但有两处风险需要处理（现已由下一小节的明度档覆盖）：

1. **L2 / L5 只有 2 种填充色**，盘面偏单调，接近用户最初抱怨的"所有瓦片长得一模一样"（只是从全白变成了双色）。→ 明度档把这两个关卡的同族符号拆开：L2 变 4 种外观（Fe T0 / Cu T1 / Zn T2 / Al T0）、L5 变 6 种（F–I 四档 + Na T0 / K T1）。
2. **L3/L4 的卤素只有 F/Cl 两张紫色**——颜色暗示"这两张是一伙的"，但只有 2 个成员凑不成族三连。这是刻意的教学点（配 `help.r3b` 说明），明度档会让 F 与 Cl 一眼可分，反而**弱化**了"同色=同一伙"的错误暗示，是额外红利。

#### 族内区分：逐 symbol 明度档（R18 裁 B，已落地）

填充色承载**族**而不承载**符号**，所以 L2 全盘只有 2 种颜色、L5 六张牌四张紫。当同屏 60% 的牌共用一种色相时，"扫视找第三张"这个动作就失效了——玩家只能逐张读符号，等于把用户最初抱怨的"所有瓦片长得一模一样"换一个色相重演一遍。

**裁决：补族内区分，但只用「逐 symbol 明度档」——不加纹样、不偏色相。**

- **不加纹样**：55px 下纹样已到空间上限，且与符号抢位置；纹样保持**族粒度**，只服务色盲通道。
- **不偏色相**：「色相 = 族」是身份通道，偏了就毁。
- 剩下可用的只有明度这一维，它不占卡面空间，是唯一还有对比度余量的通道。

**机制**：JS 把该关牌池内**同族**的 distinct symbol 按**原子序数 Z 升序**赋 `data-tier 0..3`。档位步长**不是统一值**，按各族的对比度余量分档：halogen / alkali-metal / metal-f / nonmetal / noble-gas **+4%/档**；metal-p **+3%/档**；metal-d / alkaline-earth-metal **+2%/档**；metalloid **+1%/档**。CSS 侧由 `games/game-theme.css` §2b 的 36 条 `[data-fam][data-tier]` 规则只覆盖 `--f-l` / `--f-bl`，本 GDD 不复述色值。

> 🔴 **验收硬规则（不可放宽）：同一 symbol 的所有副本必须同档。** 同元素三消靠"两张牌长得完全一样"来完成配对——若档位逐副本随机，同一个 Fe 的两张牌会深浅不同，玩家失去"这两张是一对"的唯一视觉依据，**游戏直接坏掉**。因此 `data-tier` 必须是 `symbol` 的纯函数（`tier = f(symbol)`），不得由副本序号、发牌顺序或随机数决定。验收方式：对每关盘面按 `symbol` 分组，断言每组内 `data-tier` 取值集合大小为 1。

**连带的选池硬约束**（详见 §5.8 规则三与断言 A5）：每关**同族 distinct symbol ≤ 4**，且 **`metal-d` ≤ 3**。超出后明度档的对比度余量耗尽（`metal-d` T3 = 4.42，是全表唯一低于 4.5 的组合），机制失效，只能换族而不是硬上。

**`pointer-events: none` 的三个合法用途（仅此三处）**：

1. `[data-anim="out"]`：正在飞出的牌，防止动画中途被二次点击；
2. 教学第 2 步：给 `.sg-board` 容器加 `pointer-events:none`，同时给唯一目标牌加 `pointer-events:auto`（这是「强制只能点这一张」的正确写法）；
3. 结算遮罩层下方的盘面。

**验收**：写一个手工测试脚本（quality-lead 可用）：点击每张被遮挡牌的露出区域，断言不消耗步数、槽位不变、且抖动动画被触发。

## 4. 数值与难度曲线

### 4.1 核心数值总表

| 符号 | 含义 | 取值 | 依据 |
|---|---|---|---|
| `SLOT_MAX` | 槽位容量 | **7** | 沿用羊了个羊经典值，也是本作所有张力的锚点 |
| `BENCH_MAX` | 暂存区容量 | **3** | 一次救急够用，过多会让 7 格失去意义 |
| `TILE` | 牌边长 | `clamp(44px, (100vw − 48px)/boardW, 72px)` | 375px 下 ≥ 44px（触控下限），小盘面自动放大 |
| `VISIBLE_RATIO` | 起始可点牌占比 | **≈ 33%**（= 1/层数，层数相同时解析成立） | 实测：3 层同形错位 → 恰好 1/3 可点 |
| `LAYER_OFFSET` | 层间错位 | **1 hu**（半张牌） | 上层牌落在下层四张中间，遮挡最大化且视觉最优 |
| `WITNESS_BUDGET` | DFS 节点预算 | **8000** | 实测 ≤ 8000 节点足够，最坏 45 张牌平均搜索 30–80 节点 |

**`boardW` 与 `boardH` 的定义**（供 CSS 变量注入）：

```
maxGx  = max over layers of ( off + 2×(maxN − 1) )
maxGy  = max over layers of ( off + 2×(rows.length − 1) )
boardW = (maxGx + 2) / 2          // 单位：tile。+2 因为一张牌占 2 个半格
boardH = (maxGy + 2) / 2
```

> 注意 `+2` 而不是 `+1`：一张牌的**右边缘/下边缘**在 `gx+2` 处（占 2 个半格宽），所以包围盒是 `gx..gx+2`。写成 `+1` 会少算半张牌，`--tile` 会被算大、盘面溢出。

### 4.2 层数与形状的选择依据

**为什么是 3 层（而非 2 层或 5 层）**：

- 2 层 → 起始可点 50%，遮挡感太弱，玩家几乎可以「看着选」；
- 3 层 → 起始可点 33%，且**任何一张底层牌都至少被 2 张牌压过**，拆解顺序变得非平凡；
- ≥4 层 → 起始可点 ≤25%，会出现「只有 3 张可点、且都不相关」的开局，玩家没有选择余地（实测 `pyr18` 4 层仅 17% 可点，开头极闷）。

本作 **L2–L6 全部采用 3 层**（层数与外形一致，靠 `nd` 调难度，见 §4.3）；**L1 例外采用 2 层三角**做教学，因为教学要的是「一眼看懂」，不是「烧脑」。

**轮廓形状的选择**：

| 形状 | 语法 | 视觉 | 用在哪 |
|---|---|---|---|
| 三角（1,2,3）+（1,2） | `[{off:0,rows:[1,2,3]},{off:1,rows:[1,2]}]` | 稳定、指向性强 | L1 教学 |
| 矩形 3×2 / 4×2 / 5×2 / 4×3 / 5×5 | `3 层 × rows[...]` | 像一摞牌/晶格，最像原版 | L2–L6 |

**不选菱形的原因**：菱形（`rows:[1,2,3,2,1]`）在 `off` 递增时会出现上下尖角区域的**极度稀疏**（尖角只有 1 张牌却要占 1 层），实测 20 张牌只有 17% 可点，开局压抑；且菱形在窄屏上浪费横向空间。

### 4.3 难度旋钮

> ⚠️ **本节结论已修订。** 早前版本认为「`nd` 是唯一有效旋钮、牌数几乎无影响」。**这个结论在计入同族三连后被推翻了**——实测显示牌数、族构成、`nd` 三者共同决定难度，且**族构成的权重最高**。

#### 旋钮一：族构成（权重最高，详见 §5.9）

池子里某族**恰好有 3 个成员**时，该族所有牌退化成「任意 3 张即消」→ 胜率直接冲到 90–100%。这是最强的旋钮，也是最危险的（容易无意中造成关卡失效）。**选池时先定族构成，再定 `nd`。**

#### 旋钮二：`nd`（不同元素种数）

> 实测（**不含**族匹配，纯同元素消，附录 A.3）：同一 30 张牌盘面，`nd=4` → 98%；`nd=5` → 88%；`nd=6` → 63%；`nd=7` → 32%；`nd=8` → 23%。

**为什么 `nd` 有效**：玩家的真实压力来自「槽位里躺着多少种**凑不齐**的元素」。7 格槽位 → 一旦同时出现 6–8 种不同元素，必然有元素被迫占着槽位等死。`nd` 直接决定**同时可见的可点牌上有多少种不同元素**，也就直接决定「这一点击下去是不是赌博」。

#### 旋钮三：牌数 `nTiles`（权重随族构成放大）

- **不含族匹配时**：牌数几乎不影响胜率（30 张 63% vs 45 张 53%，同 `nd=11` 量级下差异小）。
- **含族匹配时**：牌数显著影响。因为族匹配把单次决策变简单后，**失败变成累积风险**——局越长，犯致命错误的次数越多。
  > 实例：同一牌池 `F Cl Br I Na K`，36 张 → 52.8%，30 张 → 58.0%；同一牌池 `卤素4+稀有气体4`，45 张 → 33.3%，36 张 → 约 40%。

**结论：牌数是"风险累积"旋钮，不是"单次决策"旋钮。** 想让关卡更紧张但没有新元素可加时，加牌数；想加单次决策压力时，加 `nd`。

#### 硬约束

`nTiles / 3` 是三连组数，`nd` 是元素种数。若 `nd > nTiles/3`，会有元素根本没有 3 张，**非法**：

```
nd ≤ nTiles / 3
```

### 4.4 计分与连锁

```
base(type) = 100      若为「同元素三连」
           = 250      若为「同族三连」

M(chain)   = min( 1 + 0.5 × (chain − 1), 3.5 )     chain ≥ 1

matchScore = round( base(type) × M(chain) )

chain 更新规则：
   一次点击后若清除了 k 组 → chain += k        （同族三连每次 +2，见下）
   一次点击后若什么都没清   → chain  = 0

关卡结算：levelBonus = 300 × levelIndex + 100 × (未使用的道具使用次数)
```

| chain | 1 | 2 | 3 | 4 | 5 | 6+ |
|---|---|---|---|---|---|---|
| M | 1.0 | 1.5 | 2.0 | 2.5 | 3.0 | 3.5 |

**同族三连额外 +2 chain 的理由**：同族三连本身更难成（需要 3 个**互不相同**的同族元素同时在场），且是玩家用知识换来的，多给倍率成长是正当的。它不是主导策略（见 §4.5）。

**为什么倍率上限是 3.5**：7 格槽位下，理论上最多能预置 3 组待完成的对子（6 格），因此实际可达 chain ≈ 4（M = 2.5）。设 3.5 只是防御性上限，避免撤销/暂存组合打出异常值。

**连锁可达性证明**（重要，防止设计了一个永远触发不了的机制）：
```
槽位摆 A,A,B,B  (4 格) 且 A,B 各有第三张可点
点击 A  → 槽位 A,A,A,B,B → 清 A → 槽位 B,B              chain = 1
点击 B  → 槽位 B,B,B     → 清 B → 槽位 []               chain = 2
```
需要 5 格占用，7 格槽位可容纳。**连锁是可达的，且需要「预置两个对子」这种真实技巧**——这正是我们希望奖励的行为。

### 4.5 匹配规则（含 `metal` 排除论证）

#### 规则定义

| 规则 | 条件 | 收益 | 触发频率 |
|---|---|---|---|
| **同元素三连** | 槽内同一 `symbol` ≥ 3 张 | `100 × M` | 主体 |
| **同族三连** | 槽内 **3 张互不相同** 的 `symbol`，且 `category` 相同，且该 `category` ∈ 白名单 | `250 × M`，chain +2，弹族徽卡 | 取决于牌池族构成，见下 |

> ⚠️ **早前版本称同族三连「占约 10% 消除、只是辅助」，这是错的。** 触发频率完全由牌池族构成决定，跨度从 **0%（族成员 ≤2）到压倒性主导（族成员恰为 3）**。这是一个必须靠选池规则控制的变量，不是一个固定比例。详见 §5.9 与本节末尾的「族构成对平衡的影响」。

#### 白名单：只允许这 6 个族

| `category` 取值 | 中名 | 英名 | 成员数（Z ≤ 103） |
|---|---|---|---|
| `alkali-metal` | 碱金属族 | Alkali metals | 6 |
| `alkaline-earth-metal` | 碱土金属族 | Alkaline earth metals | 6 |
| `halogen` | 卤素族 | Halogens | 5 |
| `noble-gas` | 稀有气体族 | Noble gases | 6 |
| `metalloid` | 类金属族 | Metalloids | 6 |
| `nonmetal` | 非金属族 | Nonmetals | 7 |

#### ⛔ 硬性排除 `metal`

**数据事实**：`elements-zh.js` 中 `category: 'metal'` 共 **80 / 118 条 = 67.8%**。这是本站数据模型的一个已知简化（把 s 区外全部过渡金属 + 后过渡金属 + 镧系锕系塞进一个桶）。

**如果允许 `metal` 参与同族匹配**，会有两个灾难：

1. **主导策略（dominant strategy）**：金属牌之间可以任意互换凑三连（Fe + Cu + Au 就清）。玩家学会「优先抓金属」后，非金属牌变成纯负担 → 出现唯一最优解，卡片选择失去意义。
2. **教育价值归零**：把 80 个元素教成「它们都是金属」没有任何化学信息量；而「碱金属都只有 1 个价电子」是真实且有用的族规律。

**因此：`metal` 明确不参与同族匹配，但仍在卡面上显示类别色条。** 这既是平衡决策，也是教学决策。

> 🔶 **数据层建议（交主理人/用户决策，不在本轮实现）**：长期可在数据文件增加 `block: 's'|'p'|'d'|'f'` 字段，届时可开放「同区匹配」作为进阶玩法。当前 `category` 的 7 分类粒度不足以支撑更细的族匹配。

> ⚠️ **实现防错**：art-director 为配色需要，把 `metal`（80 条）按原子序数拆成了 `metal-d` / `metal-f` / `metal-p` 三个**视觉亚族**（见 §5.8）。**这个拆分只用于 CSS 取色，绝不能进入匹配逻辑。** 匹配逻辑判定同族时，必须读原始 `category` 字段并排除 `metal`；若误用视觉亚族，`metal-d`（Z 21–30/39–48/72–80/104–112，**38 个元素**）会变成一个巨大的可互换桶，直接触发上文的主导策略灾难。

#### 同族三连的教育价值（这是它存在的第一理由）

同族三连 = 一次**主动检索**。玩家为了活下来，会自己去想「还有哪个是卤素」。这条记忆的经历强度远高于读卡片。证据：这是唯一一种「玩家为了游戏利益而主动调用化学知识」的机制。

配套的**族徽卡**（非模态浮层，2.2s 自动消失，可点「看这 3 个元素」跳详情）：

| 族 | 中文一句话 | English one-liner |
|---|---|---|
| 碱金属族 | 最外层只有 1 个电子，极易失去；遇水剧烈反应，活泼性随原子序数增大而增强。 | One valence electron, eagerly given away — they react violently with water, and reactivity increases down the group. |
| 碱土金属族 | 最外层 2 个电子，活泼性仅次于碱金属；钙、镁是骨骼与叶绿素的核心。 | Two valence electrons; less reactive than the alkali metals. Calcium builds bones, magnesium sits at the heart of chlorophyll. |
| 卤素族 | 最外层 7 个电子，只差一个就满壳层，因此是最强的氧化剂一族。 | Seven valence electrons — one short of a full shell, which makes them the fiercest oxidizers in the table. |
| 稀有气体族 | 最外层已满（氦为 2，其余为 8），几乎不参与反应，故称「惰性气体」。 | A full outer shell (2 for helium, 8 for the rest) leaves almost nothing to react with — hence "inert". |
| 类金属族 | 性质介于金属与非金属之间；硅和锗是全部半导体的基石。 | Straddling metals and nonmetals — silicon and germanium underpin every semiconductor. |
| 非金属族 | 电负性高、导电导热性差；碳、氢、氧、氮搭起了生命分子的骨架。 | High electronegativity, poor conductors — carbon, hydrogen, oxygen and nitrogen form the skeleton of life. |

#### 族构成对平衡的影响（本轮实测发现，**必读**）

同族三连的威力**不是常数**，而是牌池族成员数的强函数：

| 某族在池中的成员数 `k` | 族三连可行性 | 实测胜率（30 张 / `nd=6`） | 用途 |
|---|---|---|---|
| `k ≤ 2` | **不可能** | 62.7% | 负向教学（「两个凑不成」） |
| `k = 3` | **必然可行** → 退化 | **90–100%** | ❌ **禁止** |
| `k = 4` | 可行，但第 4 个成员会占槽 | 54.0% | 正向教学 + 难度 |

- `k=3` 时，「任意 3 张该族牌」都满足「3 个互不相同」，该族的全部牌退化成「任意 3 张即消」的超级符号——**比同元素匹配更容易**。这会让关卡直接失效。
- `k=4` 时反而**比没有族匹配更难**（54.0% < 72.3% 基准）。这不是缺陷，而是一个有价值的机制张力：**族里成员太多，你反而更难凑齐 3 个**，因为第 4 个会长期占着槽位。

→ **选池硬规则（断言 A6）**：任一白名单族的成员数**不得等于 3**。完整论证与六关校验见 §5.9。

**教育价值上的额外红利**：这条规则让「族三连」的可用性本身成了教学对象。L3/L4 让玩家看到「只有 2 个，凑不成」；L5/L6 让玩家看到「有 4 个，能凑，但多出来的那个会碍事」。**同一个机制在四种族规模下呈现四种体验**，而化学上恰好对应「同族元素的多样性与周期性规律」。

### 4.6 移动端适配数值

| 屏宽 | 可用宽 | `--tile`（最宽盘面 boardW=6.0：L4 / L6） | 盘面宽 | 槽位（7 格）可行解 |
|---|---|---|---|---|
| **375px（基准）** | 375−32 = 343px | (375−48)/6 = **54.5px** | 327px | **出血**（`padding-inline:0`）+ `gap:5px` → 每格 (375−30−3)/7 = **48.9px** ✅ |

> **槽位数值已按 art-director 本轮的出血实测口径更新**：375px 下从保守口径的 44.7px（含 16px 页边距）升到 **48.9px**（出血 + padding 归零 + gap 5px，再扣 3px 槽位描边占位）。**这使槽位从"勉强合规"翻转为"满足 Apple HIG 44px"** ——即使未来恢复槽位点击也无需再补透明命中区。44.7px 仍作为含页边距的保守口径保留在 360px 行。
>
> **槽位仍是全局最紧的一处约束**：7 格 × 48.9px ≈ 342px，在 375px 上已是出血极限。实现时必须**先做槽位、再排盘面**——盘面可以缩（`--tile` 是连续的），槽位缩不了。

若某设备下 375px 仍溢出 → 备选：槽位牌视觉缩至 `--tile × 0.86`，但用透明 `::before` 把命中区补到 44×44。

#### 纵向高度预算（与 art-director 的规格对齐）

iPhone SE 竖屏（375×667）实测固定开销（数据来自 `docs/visual/game-visual-spec.md §3.5`）：

```
导航 64 + 紧凑 HUD 52 + 槽位轨 61 + 间距 32 = 固定 209px
667 − 209 = 458px  → 可用给牌堆 ≈ 450px（留地址栏余量）
```

**硬约束：牌堆纵向不超过 6 行**（按每行 ≤ 瓦片高 72px + gap 8px = 80px 最坏情况估算）。

本作六关的实际高度：

| 关卡 | `maxGy` | 牌堆高（tile 行） | @72px 最坏像素高 | 占 450px 预算 | 判定 |
|---|---|---|---|---|---|
| L1 | 4 | 3.0 | 240px | 53% | ✅ |
| L2–L4 | 4 | 3.0 | 240px | 53% | ✅ |
| L5–L6 | 6 | **4.0** | **320px** | **71%** | ✅ |

> **结论：本作最大牌堆只有 4 行，占预算 71%，距 6 行上限还有 2 行余量。因此不需要纵向滚动，也不需要把瓦片缩到 40px。** 牌堆可完全落在首屏内。

**若未来新增关卡，`boardH ≤ 6` 是硬约束**，须在关卡配置加载时断言。想让关卡更难请加 `nd`（§4.3），**不要加层数或行数**——加高会在手机上直接溢出，而加 `nd` 不影响布局且难度曲线更陡。

#### 槽位触控规格

- **v2 删除「点槽位撤回」功能，槽位是纯展示容器**，不承载高频触控。
  > ⚠️ 现版 `sheep_game.html` 里每个已填充槽位都有一个 20×20px 的红色 `remove-btn`，点击可把该元素**直接拿回**——这实际上是一个**无限免费的撤销**，让 7 格槽位形同虚设（也是现版深度不足的次要原因之一）。v2 必须删除。
- 因槽位无触控目标，375px 下每格 **48.9px**（出血口径）已越过 Apple HIG 44px；360px 下的 44.7px 保守口径也合规（WCAG 2.2 SC 2.5.8 的 ≥24px 更是绰绰有余）。
- 即使实现保留了槽位上的点击交互（不建议），48.9px 已满足 HIG，无需再补透明命中区；仅 320px 极端屏（44.0px）需注意不要加内边距。

### 4.7 道具数值

| 道具 | 中文 | English | 次数 | 解锁关 | 效果 | 是否影响可解性 |
|---|---|---|---|---|---|---|
| `undo` | 撤销 | Undo | **3 / 关** | L1 | 回滚到上一次点击前的完整状态（含被消除的牌、分数、连锁） | ✅ 安全（纯回退） |
| `eject` | 移出 | Set aside | **1 / 关** | L3 | 把槽内最多 3 张移到「暂存区」（3 格，不计入 7 格上限），点击暂存牌可放回槽位 | ✅ 安全（严格增加容量） |
| `shuffle` | 洗牌 | Shuffle | **1 / 关** | L5 | 保持几何与槽位不变，重新分配盘面牌的 `symbol`（保持全局 symbol 计数不变） | ⚠️ 需重跑 DFS 验证，失败则回滚并退还次数 |
| `hint` | 提示 | Hint | **1 / 关** | L4 | 从当前状态重跑 DFS，高亮「按解路径的下一张」0.8s | ✅ 安全（只读） |

**道具设计原则**：
- **`undo` 是主力**，3 次足够覆盖前中期所有失误，也是"免费复活"的载体。
- **`eject` 是救急**，不解决"没牌可配"，只解决"槽位爆满"，语义清晰不混淆。
- **`shuffle` 是重开**，代价最高（1 次），只在走投无路时用。**必须实现回滚**：若重掷后 DFS 验证失败则原子回滚。
- **`hint` 是教学**，晚解锁（L4），因为太早给会养成"点提示代替思考"的习惯。

**为什么不用「看广告换道具」**：纯静态站，无广告 SDK。改用**每关首次失败免费 +1 次撤销复活**（见 §7.3），在无商业化前提下给出同等情绪缓冲。

## 5. 关卡设计

### 5.1 六关配置总表

> `rows` 中的数字是「该层该行的牌数」。所有层统一 `off = layerIndex × 1`（半格错位）。
> **硬约束校验**：`Σ(牌数) % 3 === 0` 全部满足 ✅；`nd ≤ 牌数/3` 全部满足 ✅。

| # | 关卡名（中 / 英） | 层数 | 每层 rows | 总牌数 | `nd` | 元素池 | 起始可点 | 实测人类胜率 | 道具 | 化学教学焦点 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 试炼·小三角 / First Triangle | 2 | `[1,2,3]`, `[1,2]` | **9** | **3** | Fe Cu O | 3 | **100.0%** ±0.0 | undo×3 | 只看「遮挡」这一个概念 |
| 2 | 石墨层 / Graphite Layer | 3 | `[3,3]` × 3 | **18** | **4** | Fe Cu Zn Al | 6 | **97.8%** ±1.3 | undo×3 | 过渡金属；全 `metal`，**族三连不可能** |
| 3 | 岩盐晶格 / Rock Salt | 3 | `[4,4]` × 3 | **24** | **5** | F Cl Na K Fe | 8 | **80.2%** ±3.5 | undo×3, eject×1 | **不完整的族凑不成**：卤素只有 2 个、碱金属只有 2 个 |
| 4 | 层状解理 / Cleavage | 3 | `[5,5]` × 3 | **30** | **6** | F Cl Na K Fe Cu | 10 | **60.6%** ±4.3 | undo×3, eject×1, hint×1 | 同上，池子更大（+Cu） |
| 5 | 尖晶石塔 / Spinel Tower | 3 | `[4,4,4]` × 3 | **36** | **6** | F Cl Br I Na K | 12 | **52.8%** ±4.4 | undo×3, eject×1, shuffle×1, hint×1 | **卤素凑满 4 个 → 族三连首次真正可用**，族徽卡首现 |
| 6 | 元素矿脉 / Element Vein | 3 | `[5,5,5]` × 3 | **45** | **7** | F Cl Br I He Ne Al | 15 | **44.4%** ±4.4 | 全部各 1 次起 | **对照**：卤素够 3 个能配；稀有气体只来 2 个，凑不成 |

> **胜率为实测值**（N=500 / 关，95% 置信区间，**已计入同族三连**），非估计。方法见附录 A.3。
> **难度单调性**：100.0 → 97.8 → 80.2 → 60.6 → 52.8 → 44.4，逐关递减。
> 相邻档位置信区间：L5 为 [48.4, 57.2]，L6 为 [40.0, 48.8]，**在 48.4–48.8 有 0.4pp 的极窄重叠**；点估计相差 8.4pp。结论：可辨识，但 L5/L6 的区分度弱于前四关（见 §5.7 观察项 O2）。
> **道具随难度解锁**：`eject` 起于 L3、`hint` 起于 L4、`shuffle` 起于 L5。
> **族三连可用性在 L1–L4 全程为「否」**（牌池族成员 ≤2），L5 起为「是」（族成员 4）。跳变点即 L4→L5，见 §5.9。

### 5.2 逐关详细配置

#### L1 · 试炼·小三角（教学关）

```js
{
  id: 1,
  layers: [ { off:0, rows:[1,2,3] }, { off:1, rows:[1,2] } ],
  symbols: ['Fe','Cu','O'],          // 3 种 × 3 张 = 9
  nd: 3,
  props: { undo:3, eject:0, shuffle:0, hint:0 },
  teaching: 'occlusion'              // 只教遮挡
}
```

- **几何**：底层 6 张（三角），上层 3 张。起始仅 3 张可点。
- **为什么 `nd=3`**：9 张牌 / 3 种 = 每种恰好 3 张 → **数学上不可能失败**（每次点满 3 张同类必消）。这是教学关应有的宽容度。
- **为什么选 Fe / Cu / O**：铁和铜是玩家最熟悉的金属，氧最有存在感；且 `metal × 2 + nonmetal × 1` → **同族三连不可能触发**（只有 1 个非金属、2 个金属且 `metal` 被排除），保证 L1 只教一个概念。
- **教学 3 步**：见 §6.2。

#### L2 · 石墨层

```js
{
  id: 2,
  layers: [ {off:0,rows:[3,3]}, {off:1,rows:[3,3]}, {off:2,rows:[3,3]} ],
  symbols: ['Fe','Cu','Zn','Al'],    // 4 种
  nd: 4,
  props: { undo:3 },
  teaching: 'layering'               // 教「层层拆」的节奏
}
```

- 3 层同形错位 → 起始可点 6/18 = 33%（解析值 = 1/3，与层数相同的情形严格成立）。
- 4 种元素全为 `metal` → **同族三连被 `metal` 排除规则天然屏蔽**，玩家在 L2 仍然只需要理解「凑 3 张一模一样」。
- 18 张 / 6 组三消，一局约 60–90 秒。

#### L3 · 岩盐晶格（**先教失败条件**：不完整的族）

```js
{
  id: 3,
  layers: [ {off:0,rows:[4,4]}, {off:1,rows:[4,4]}, {off:2,rows:[4,4]} ],
  symbols: ['F','Cl','Na','K','Fe'],   // 卤素 2 个 + 碱金属 2 个
  nd: 5,
  props: { undo:3, eject:1 },
  teaching: 'incomplete_family'        // 教「凑不成族」
}
```

- **关键设计（本轮修订后的核心改动）**：池子里卤素只有 `F/Cl` 两个、碱金属只有 `Na/K` 两个 → **族三连在这一关数学上不可能触发**。
- **为什么要故意让新机制在本关不可用**：族三连的教育价值来自「**至少 3 个不同的同族元素**」这个条件。先让玩家看到两对凑不成族的牌，他才会理解条件存在；直接给他能配的池子，他学到的只是"点对了就消"。
  > 这是教学顺序的刻意选择：**先建立边界，再给能力。**（§5.6 的「第一分钟」规则要求新机制必须有明确的教学时刻，负向教学同样算。）
- 首次解锁 `eject`：`nd=5` 时槽位压力开始真实，需要一个救急阀门。
- 实测 80.2% ±3.5%（N=500）。

#### L4 · 层状解理

```js
{
  id: 4,
  layers: [ {off:0,rows:[5,5]}, {off:1,rows:[5,5]}, {off:2,rows:[5,5]} ],
  symbols: ['F','Cl','Na','K','Fe','Cu'],   // L3 的池子 + Cu
  nd: 6,
  props: { undo:3, eject:1, hint:1 },
  teaching: 'bigger_pool'              // 池子更大，但族仍不完整
}
```

- 池子与 L3 同构（两个不完整族 + 2 个孤立金属），只是多一个 `Cu`、牌数从 24 涨到 30 → **难度来源是"更多符号抢槽位"**，而不是新的机制。
- 首次解锁 `hint`：`nd=6` 时人已经会卡住，给一次提示能显著降低弃游率。
- 30 张牌，盘面 6.0 × 3.0 tile → 375px 下 `--tile` = (375−48)/6 ≈ 55px。
- 实测 60.6% ±4.3%（N=500）。

#### L5 · 尖晶石塔（**族三连首次真正可用**）

```js
{
  id: 5,
  layers: [ {off:0,rows:[4,4,4]}, {off:1,rows:[4,4,4]}, {off:2,rows:[4,4,4]} ],
  symbols: ['F','Cl','Br','I','Na','K'],   // 卤素凑满 4 个！
  nd: 6,
  props: { undo:3, eject:1, shuffle:1, hint:1 },
  teaching: 'family_unlock'
}
```

- **卤素从 2 个补齐到 4 个（`F/Cl/Br/I`）** → 本关起，`F+Cl+Br`、`F+Br+I` 等任意 3 个不同卤素都能成族三连。**族徽卡在这一关首次真正出现。**
- **这是全局第一个、也是最需要仪式感的机制解锁点**：进入 L5 时给一次性的机制提示条「**新：同族三连** 三个不同的卤素也能一起消除」，不做强制教学（L1 的教学已经教会操作，这里只补规则）。
- 碱金属 `Na/K` 仍只有 2 个 → 保持 L3 学到的对照：「卤素够 3 个能配，碱金属只有 2 个不能配」。**同一关内正反两例并存，是最有效的规则教学。**
- 首次解锁 `shuffle`：`nd=6` + 36 张牌，是第一个「真的会卡死」的难度。
- 3 层 × 3 行 = 盘面 5.0 × 4.0 tile，375px 下 `--tile` ≈ 65px。
- 实测 52.8% ±4.4%（N=500）。

#### L6 · 元素矿脉（终局）

```js
{
  id: 6,
  layers: [ {off:0,rows:[5,5,5]}, {off:1,rows:[5,5,5]}, {off:2,rows:[5,5,5]} ],
  symbols: ['F','Cl','Br','I','He','Ne','Al'],   // nd = 7（已由用户拍板，原 8）
  nd: 7,
  props: { undo:3, eject:1, shuffle:1, hint:1 },
  teaching: 'p_block_contrast'
}
```

- **主题**：卤素族（第 17 族）与稀有气体族（第 18 族），同周期相邻但性质处于两个极端（最想抢电子 vs 完全不抢）。这是中学化学最有戏剧性的一组对照。
- **牌池的对照结构**：卤素 **4 个**（可配族三连）+ 稀有气体 **2 个**（`He/Ne`，凑不成）+ `Al`（孤立）。
  → 玩家在同一屏里同时看到「够 3 个能配」和「只有 2 个不能配」，这正是 L3 建立、L5 验证的规则的终局应用。
- 45 张牌 / 15 组三消，盘面 6.0 × 4.0 tile，375px 下 `--tile` ≈ 55px。
- **实测 44.4% ±4.4%（N=500，已计入同族三连）。** 这是全部 `nd=7` 候选池中最难的一档（对照：`卤素4+稀有气体4` 的旧 `nd=8` 方案为 32.2%，已被用户否决为过难）。
- **为什么不把稀有气体也凑满 4 个**：会让 `nd` 回到 8（违背用户决策）；且实测 `稀有气体4` 方案在 45 张牌下只有 51.2%，反而**比本方案更容易**（因为它把卤素稀释成 2 个，失去了一条族线）。**本方案是 nd=7 约束下难度最高的解。**

### 5.4 牌池符号的硬性排除

> ⚠️ **实现必读**：`elements-zh.js` 中 Z = 104–118 的元素名称是 CJK 扩展 B/C 区罕用字（𬬻 𬭊 𬭳 𬭛 𬭶 鿏 𫟼 𬬭 鿔 鿭 𫓧 镆 𫟷 鿬 鿫）。**许多手机默认字体没有这些字形，会渲染成豆腐块（□□）**，直接毁掉卡面。

**规则：所有关卡的 `symbols[]` 只能取 Z ≤ 103 的元素。**

已按此规则修正的族成员数：

| 族 | 全量 | Z ≤ 103 | 被排除 |
|---|---|---|---|
| halogen | 6 | **5**（F Cl Br I At） | `Ts`(117) |
| noble-gas | 7 | **6**（He Ne Ar Kr Xe Rn） | `Og`(118) |
| alkali-metal | 6 | 6 | 无 |
| alkaline-earth-metal | 6 | 6 | 无 |
| metalloid | 6 | 6 | 无 |
| nonmetal | 7 | 7 | 无 |

→ 卤素族 / 稀有气体族的三连仍然可达（需 3 种不同，可用 5 / 6 种）。**本作 6 个关卡全部只用 Z ≤ 103 的元素，此问题在当前关卡表下不会发生**，但实现时必须断言 `symbol.atomicNumber <= 103`。

### 5.5 难度曲线可视化

以下为**实测胜率**（N=500，含同族三连），非估计值：

```
胜率
100% ┤ ● L1  9张 nd3  Fe Cu O              (族三连不可用)
 98% ┤  ● L2  18张 nd4  Fe Cu Zn Al        (族三连不可用)
 80% ┤     ● L3  24张 nd5  F Cl Na K Fe    (族不完整 → 不可用)
 60% ┤        ● L4  30张 nd6  F Cl Na K Fe Cu  (族不完整 → 不可用)
 53% ┤           ● L5  36张 nd6  F Cl Br I Na K  (卤素4 → 可用)
 44% ┤              ● L6  45张 nd7  F Cl Br I He Ne Al (卤素4可用 / 稀有2不可用)
     └──┬────┬────┬────┬────┬────┬──
       L1   L2   L3   L4   L5   L6
     100.0 97.8 80.2 60.6 52.8 44.4   ← 单调递减 ✅
```

**两点值得注意**：

1. **曲线单调，但有两个"台阶"**：L2→L3（−17.6pp）和 L3→L4（−19.6pp）是陡降，L4→L5→L6 是缓降（−7.8、−8.4）。这不是设定不匀，而是**族三连可用性在 L5 发生了跳变**：L3/L4 完全不可用（族不完整），L5 才开始可用。跳变点必然产生台阶。
2. **族三连的引入被刻意推迟到 L5**：L1–L4 全程不可用。这既是教学顺序（先教边界，再给能力），也是避免 `k=3` 退化结构的必然结果（见 §5.9）。

### 5.6 每关的「第一分钟」设计

关卡好不好玩，取决于玩家在前 5 次点击里有没有理解「这游戏要我干嘛」。因此每关开局必须满足：

1. **开局可点牌里，至少有一组能凑成对子**（让玩家第一次点击就产生"推进感"）；
2. **开局可点牌里，不允许同时出现 ≥ `nd - 1` 种不同元素**（否则第一次点击就是纯赌博）；
3. **第一组消除必须在 ≤ 4 次点击内发生**。

> 这三条是**生成器后置校验**（post-filter），实现时在 S4 采纳 assignment 前额外检查。若不满足则重掷。成本可忽略（首掷成功率已 ≈ 1.0，加过滤后预计 1–3 次）。

### 5.7 L6 难度：已执行 `nd=7`，保留的观察项

**状态：✅ 已执行。** 用户已拍板 `nd: 8 → 7` 立即生效，不再采用"上线后收数据再定"的路径。L6 牌池随之改为 `F Cl Br I He Ne Al`（`nd=7`）。

| 牌池 | F Cl Br I He Ne Ar Kr | **F Cl Br I He Ne Al** |
| 实测胜率（N=500，含族三连） | 32.2% ±4.1 | **44.4% ±4.4** |

### 5.8 元素池选池约束（色相可读性）

> 来源：`docs/visual/game-visual-spec.md §2`（art-director 实测）。**这是选池的硬规则，新增关卡必须校验。**

站点色盘在青绿带（H147°–192°）堆了 4 个族，同屏 3 个以上时色相几乎不可分：

| 族 | 色值 | 色相 |
|---|---|---|
| `metalloid` 类金属 | `#96ceb4` | H152 |
| `noble-gas` 稀有气体 | `#98d8c8` | H165 |
| `alkaline-earth-metal` 碱土金属 | `#4ecdc4` | H176 |
| `metal-d` 过渡金属 | `#45b7d1` | H191 |

**规则一：每关元素池最多包含上述 4 族中的 1 个。**

**规则二：`nonmetal`（`#ffeaa7` 黄）与 `metal-p`（`#e08a3c` 青铜）不可同屏**（黄/青铜色相接近）。

**规则三：每关同族 distinct symbol ≤ 4，且 `metal-d` ≤ 3。**（明度档可读性，本轮新增）

> 注：`metal-d` / `metal-f` / `metal-p` 是 art-director 按原子序数从 `metal`（80 条）拆出的**视觉亚族**，仅用于配色，不参与任何游戏逻辑（`metal` 仍整体排除在同族匹配外，见 §4.5）。
> **拆分口径以 art-director 的 `familyOf()` 为准（文档 §1.1）**：`metal-d` 过渡 = Z 21–30 / 39–48 / **72–80 / 104–112**（共 38 个）；`metal-f` 镧锕 = Z 57–71 / 89–103；`metal-p` 后过渡 = 其余金属。
> ⚠️ 早前本 GDD 写的"过渡 = Z 21–30/39–48/72–80"（29 个）**漏了 104–112（Rf–Cn）**，以 38 个为准。**对玩法零影响**（六关最大 Z=53），仅影响断言计数。

> 🔴 **盘面瓦片的填充色就是分类色**（非卡片图），因此 §5.8 的青绿带规则不只是配色问题，而是**盘面可读性的硬前提**——同屏 4 个青绿带族会让填充色几乎无法区分。这也让断言 A5 从"体验优化"升级为"功能必需"。

#### 六关实测校验结果（按修订后的牌池）

| 关卡 | 元素池 | 出现的亚族 | 青绿带族数 | 黄/青铜冲突 | 判定 |
|---|---|---|---|---|---|
| L1 | Fe Cu O | `metal-d`, `nonmetal` | 1 | 无 | ✅ |
| L2 | Fe Cu Zn Al | `metal-d`, `metal-p` | 1 | 无（无 `nonmetal`） | ✅ |
| L3 | F Cl Na K Fe | `halogen`, `alkali-metal`, `metal-d` | 1 | 无 | ✅ |
| L4 | F Cl Na K Fe Cu | `halogen`, `alkali-metal`, `metal-d` | 1 | 无 | ✅ |
| L5 | F Cl Br I Na K | `halogen`, `alkali-metal` | **0** | 无 | ✅ |
| L6 | F Cl Br I He Ne Al | `halogen`, `noble-gas`, `metal-p` | 1 | 无（无 `nonmetal`） | ✅ |

**结论：六关全部满足规则一、二。** 新增关卡时须在 S1 加载阶段断言此规则（断言 A5 的第一半）。

#### 规则三校验：同族符号数上限与明度档落点

为什么需要上限：R18 的族内区分靠**逐 symbol 明度档**（§3.3），档位步长被族的对比度余量卡死。`metal-d` 每档只有 **+2%** 明度，到 T3 时对白字对比度 **4.42**——是全表唯一跌破 4.5 的组合。所以 `metal-d` **最多 3 个符号**（T0/T1/T2）；其余族最多 4 个（T0..T3）。

| 关卡 | 同族符号 → 明度档（Z 升序） | 单族最多符号数 | `metal-d` 数 | 判定 |
|---|---|---:|---:|---|
| L1 | `metal-d`: Fe(T0) Cu(T1)；`nonmetal`: O(T0) | 2 | 2 | ✅ |
| L2 | `metal-d`: Fe(T0) Cu(T1) Zn(T2)；`metal-p`: Al(T0) | 3 | **3（恰达上限）** | ✅ |
| L3 | `halogen`: F(T0) Cl(T1)；`alkali-metal`: Na(T0) K(T1)；`metal-d`: Fe(T0) | 2 | 1 | ✅ |
| L4 | `halogen`: F(T0) Cl(T1)；`alkali-metal`: Na(T0) K(T1)；`metal-d`: Fe(T0) Cu(T1) | 2 | 2 | ✅ |
| L5 | `halogen`: F(T0) Cl(T1) Br(T2) I(T3)；`alkali-metal`: Na(T0) K(T1) | **4（恰达上限）** | 0 | ✅ |
| L6 | `halogen`: F(T0) Cl(T1) Br(T2) I(T3)；`noble-gas`: He(T0) Ne(T1)；`metal-p`: Al(T0) | **4（恰达上限）** | 0 | ✅ |

**结论：六关全部满足规则三。** 两处恰好压在上限上，说明余量已用尽：

- **L2 是 `metal-d` 的极限**（Fe/Cu/Zn = T0/T1/T2），全作最差对比度 **4.86** 就出现在这里。它没跌破线，靠的是 L2 以 **72px** 渲染、且元素名作为冗余通道。
- **L5 / L6 是卤素的极限**（F/Cl/Br/I = T0..T3），但卤素每档 +4%、T3 仍有充足余量，安全。

→ **未来若某关想要 4 个 `metal-d` 符号，明度档机制会直接跌破 4.5，必须换族，不能靠调参硬上。** 这条与规则一/二一起并入断言 A5，在加载阶段校验（`metal-d` 计数 ≥ 4 即抛错）。

> 三重编码兜底：每个族同时有**色相 + 明度档 + 纹样**，因此即使规则被违反也不会信息丢失；但选池约束是最有效手段，应优先遵守。

**L5 为何青绿带族数为 0、L6 为 1**：卤素（`#dda0dd` 紫）与碱金属（`#ff6b6b` 红）都在色相环的另一侧。**L5 是全局色相最干净的一关**（0 个青绿带族），这正好补偿它作为机制解锁关的认知负荷。

### 5.9 元素池族构成约束（**玩法硬规则**，本轮修订新增）

> ⚠️ 这是与色相约束（§5.8）**互相独立**的另一条选池规则，来自本轮实测发现的平衡漏洞。两者都必须满足。

#### 发现：恰好 3 个成员的完整族是一个退化结构

实测（30 张牌盘面，`nd=6`，N=300，含族三连）——**唯一变量是族构成**：

| 牌池 | 族构成 | 胜率 | 结论 |
|---|---|---|---|
| `F Cl Br Na K Rb` | 2 个完整族（各 3 人） | **100.0%** | ❌ 退化 |
| `F Cl Br` + 3 金属 | 1 个完整族（3 人） | **90.0%** | ❌ 过易 |
| `F Cl Na K Fe Cu` | 2 个不完整族（各 2 人） | 62.7% | ✅ |
| `Fe Cu Zn Al Ni Sn` | 无族 | 72.3% | ✅ 基准 |
| `F Cl Br I` + 2 金属 | 1 个族（**4 人**） | **54.0%** | ✅ 偏难 |

**根因**：若池中某族**恰好有 3 个不同成员**，那么"任意 3 张该族牌"必然满足「3 个互不相同」——包括 3 张完全不同的。这使该族的全部牌（如 9 张）变成一个「任意 3 张即消」的超级符号，**比普通同元素匹配更容易**。这就是 L3/L4 早前版本胜率冲到 98–99% 的原因。

**反直觉的推论**：**4 个成员的族反而让关卡更难**（54% < 72% 基准）。因为它把"3 张相同"稀释成"6 张中凑 3 种不同"，第 4 个成员会长期占据槽位。这不是 bug，而是一个漂亮的机制——**"族里成员太多时，你反而更难凑齐 3 个"**。

#### 规则（新增，须断言）

```
对每个白名单族 c（6 个族，排除 metal），设该族在关卡的 symbols[] 中出现 k 次：
  允许 k ∈ {0, 1, 2, 4, 5, 6, 7}
  禁止 k === 3          ← 退化结构，会把关卡变成 90%+ 胜率
```

- `k ≤ 2`：族三连**不可能**触发 → 用于「负向教学」（L3/L4）
- `k ≥ 4`：族三连可触发，但存在"多余成员占槽"的张力 → 用于「正向教学」（L5/L6）

#### 六关合规校验

| 关卡 | 各族成员数 | 是否含 k=3 | 判定 |
|---|---|---|---|
| L1 | nonmetal 1 | 否 | ✅ |
| L2 | 全 `metal`（排除） | 否 | ✅ |
| L3 | halogen 2, alkali 2 | 否 | ✅ |
| L4 | halogen 2, alkali 2 | 否 | ✅ |
| L5 | halogen **4**, alkali 2 | 否 | ✅ |
| L6 | halogen **4**, noble 2 | 否 | ✅ |

→ 断言 **A6：任一白名单族的成员数 ≠ 3**。

#### 为什么这条规则比 §5.8 的色相规则更重要

色相规则影响**可读性**（玩家看不清，但游戏逻辑正确）；族构成规则影响**难度本身**（关卡从 62% 变成 100%）。前者是体验问题，后者是设计失效。

### 6.2 首关 3 步教学（L1，仅首次进入时触发）

**设计约束**：教学必须是**盘面上真实的一局**，不是模拟动画。玩家在教学中做的每一步都是有效的游戏进度。

| 步 | 触发 | 系统动作 | 玩家动作 | 文案（中） |
|---|---|---|---|---|
| **①「点它」** | L1 加载完成 | 给 `.sg-board` 加 `pointer-events:none`，给一张**未被遮挡**的顶层牌加 `pointer-events:auto` + 呼吸光晕。底部气泡指向它。 | 点那张牌 | 「点一张**露在最上面**的牌，它会进入下面的槽位。」 |
| **②「它被压住了」** | ①完成 | 保持 `.sg-board` 遮罩，改为给一张**被遮挡**的牌加 `pointer-events:auto` + 灰化 + 一个「链条锁」图标。 | 点那张（会抖动） | 「这张牌被上面的牌**压住了**。先清掉压着它的牌，才轮得到它。」 |
| **③「三张一样就消除」** | ②完成 | 移除遮罩，全场可点。给「能凑成第 3 张」的那张牌呼吸光晕。 | 点到槽位出现 3 张同元素 → 触发消除 | 「同样元素的**三张**会自动消除，腾出槽位。槽位有 7 格——满了就输。」 |

**技术要点**：
- 教学状态机独立于游戏状态机，只拦截「输入」和「高亮」，不修改盘面。
- 教学未完成时，**道具条置灰**（避免玩家在教学中乱点道具）。
- 教学进度存 `localStorage: cw_sheep_v2_tutorial_done`，第二关起完全不出现。
- **跳过按钮**：右下角常驻「跳过教学」，因为重复玩家（清过缓存又回来的）会很烦。

### 6.4 失败态（S-05）

触发：`slot.length >= 7`（在消除判定之后）。

```
┌──────────────────────────────┐
│     槽位满了                  │
│                              │
│   7 格全满，没有凑成三连。     │
```

- **免费复活**：秒回滚到"失败前一步"，并**额外赠送 1 次撤销**（也就是说它总是有效：回滚 + 多一次额度）。
- 第二次失败 → 「免费复活」按钮置灰，文案改为「本关免费复活已用完」。
- **失败原因必须说清楚**：「7 格全满，没有凑成三连」——玩家永远知道自己是"贪了"，而不是"被系统坑了"。

|---|---|---|
| 「重新开始」（对局中，顶栏/帮助内） | 二次确认（防误触）→ 用**同一 seed** 重开本关 | 恢复满额 |
| 「再玩一次」（胜利态） | 用**新 seed** 重开本关 | 恢复满额 |
| 「重新开始」（失败态） | 用**新 seed** 重开本关 | 恢复满额 |
| 切换关卡 | 载入目标关 | 恢复满额 |

> **为什么「重新开始」要同 seed**：玩家会想"我再走一遍，刚才那步走错了"。同 seed 让这个意图成立。而"再玩一次"是想要新局。这是一个很容易被忽略但体验差异巨大的细节。

### 6.7 可访问性

| 项 | 要求 |
|---|---|
| 触控目标 | 所有可点元素 ≥ 44×44px（牌本身即命中区，最小档 54.5px 远超；**槽位是纯展示容器、不承载触控**，无需补命中区，其 48.9px 已顺带满足 HIG） |
| 键盘 | 所有牌 `tabindex` 可达（DOM 顺序 = 层序 + 行序 + 列序）；`Enter`/`Space` 激活；`Esc` 关闭浮层 |
| 焦点可见 | `:focus-visible` 有 2px 高对比描边（不依赖颜色单独传达） |
| 屏幕阅读器 | 盘面 `role="grid"`；每张牌 `role="gridcell"` + `aria-label="铁 Fe 26号 过渡金属 · 可点击"` / `"… · 被 2 张牌压住"`；槽位 `aria-live="polite"` 播报「已消除三张铁，槽位 2/7」 |
| **视觉降级不影响语义** | 卡面在 <55px 时**视觉上**隐藏原子序数与元素名（§3.3 卡面分档），但 `aria-label` **始终包含完整信息**（名称 / 符号 / 原子序数 / 类别 / 可否点击）。屏幕阅读器用户在任何尺寸下都拿到全部信息 |
| **状态不靠单一通道** | 可否点击 = **描边强度 + 族色辉光**（主）+ 内凹阴影 / `scale(.94)`（辅）；族别 = 色相 + **明度档** + 纹样（三通道）。任一通道失效仍可判别 |
| **明度通道已被族内档位占用** | 因为 `data-tier` 用掉了填充明度来表达"同族不同符号"，**遮挡态不得再把明度当信号**——两者会互相抵消（T3 极亮牌压暗后可能比 T0 亮的牌还亮）。这与实测结论一致：明度 ΔL 最高仅 0.021，本就扛不起遮挡信号（§3.3 通道强度表） |
| 动效 | `@media (prefers-reduced-motion: reduce)` → 所有 transition/animation 时长 → 0.01ms；飞入改为直接出现；抖动改为描边闪烁 |
| 色觉 | 族别不只靠颜色区分：族徽卡有族名文字 + 图标；`metal` 排除同族匹配后，颜色不再是唯一信息载体 |

## 7. 边界与失败态

### 7.1 失败条件（穷举）

| # | 条件 | 判定时机 | 处理 |
|---|---|---|---|
| F1 | `slot.length >= 7` | **在消除循环之后** | 失败：槽位溢出 |
| F2 | `alive.size > 0` 但无任何 `!blocked` 的牌 | 每次状态变更后 | **理论上不可能**（层数最大的活牌必不被遮挡）。若发生 = 程序 bug → 记录到 console，按失败处理并显示"内部错误，请重开" |
| F3 | 生成器 40 次重掷仍无法产出有解盘面 | 关卡加载时 | 降 `nd` 重试；若 `nd=3` 仍失败 → 回退到 L1 的固定盘面（内置常量，绝不联网） |

> **没有 F4「无解局面」**。因为 S4 生成器在采纳 assignment 前已经证明有解。这是支柱三的技术兑现——**把"检测无解"这个难题，用"保证有解"绕过去了。**

### 7.2 必须处理的边缘情况（EDGE 清单）

| ID | 场景 | 期望行为 | 为什么容易写错 |
|---|---|---|---|
| **EDGE-01** | 槽位 6 格，点击的第 7 张恰好凑成三消 | **判定为成功消除，槽位回到 4 格，不判负** | 若先查 `slot.length >= 7` 再消除 → 误判失败。**必须先消除后判定** |
| **EDGE-02** | 一次点击同时凑成「A×3」和「B×3」 | 两组都消，`chain += 2`，各按各自 `base` 计分 | 单次 `if` 而非 `while` 会漏掉第二组（现版代码正是这个 bug） |
| **EDGE-03** | 一次点击同时满足同元素与同族 | 优先同元素（同元素 base 低但确定；族徽卡留到下次） | 两条规则都命中时会重复清除同一批牌 |
| **EDGE-04** | 点击被遮挡牌的**露出部分** | 抖动 + 高亮遮挡者，**不消耗任何东西** | 若用 `pointer-events:none` → 点击穿透到容器，无任何反馈（见 §3.3） |
| **EDGE-05** | 快速连点同一张牌 | 只处理第一次；动画期间该牌 `pointer-events:none` | 两次点击会重复入槽 |
| **EDGE-06** | 撤销后立刻用洗牌 | 洗牌必须基于**撤销后**的状态与 `rngState` | 快照不含 `rngState` 会导致洗牌结果不可重现 |
| **EDGE-07** | 洗牌后盘面变得不可解 | 洗牌前先验证，失败则**原子回滚并退还次数** | 只回滚 symbol 不回滚槽位会造成 ghost 牌 |
| **EDGE-08** | 暂存区 3 格满时再按「移出」 | 按钮置灰；提示「暂存区已满，先把牌放回槽位」 | — |
| **EDGE-09** | 暂存区的牌与槽内牌凑成三连 | **不自动消除**。只有「槽内」参与匹配，暂存牌必须先放回槽位 | 若暂存牌参与匹配，暂存区就变成了 10 格槽位 |
| **EDGE-10** | 最后一组三消后牌面清空 | 胜利。若此时槽位还有残留 → **不是胜利**（数据异常，见 F2 处理） | — |
| **EDGE-11** | 盘面只剩 1 张牌、槽位 0 张 | 不可能：每 symbol 数量是 3 的倍数且同元素匹配 → 剩余必然是 3 的倍数 | — |
| **EDGE-12** | 窗口旋转 / 键盘弹出 / resize | 只重算 `--tile` 与 `--bw/--bh`，**不重算几何**（`gx/gy/layer` 是数据，不是布局） | 重算几何会导致层错位与遮挡图失效 |
| **EDGE-13** | `localStorage` 被禁用（隐私模式） | 用内存变量兜底，游戏可正常玩，只是不保存进度 | `JSON.parse(null)` 或 `setItem` 抛异常会白屏 |
| **EDGE-14** | 同一元素在盘面出现 4 张以上（撤销/洗牌后可能出现） | 匹配逻辑按 `count >= 3` 处理，一次清 3 张 | 硬编码 `=== 3` 会卡死 |
| **EDGE-15** | 教学第 2 步，被指定为「被遮挡」的那张牌被撤销/洗牌动了 | 教学只在 L1 且 L1 无洗牌、撤销在教学期禁用 → 不可达 | 若将来教学延长，需加保护 |

### 7.3 失败兜底策略（无广告场景）

| 层级 | 机制 | 说明 |
|---|---|---|
| L1 预防 | 生成器保证有解 | 消灭「本来就没解」这一类失败 |
| L2 预警 | 槽位 6 格时高亮 + 播报 | 让失败可预期（大部分失败发生在这一格） |
| L3 缓冲 | 每关首次失败免费回滚 + 送 1 撤销 | 无商业化前提下的情绪兜底 |
| L4 自选 | `undo` × 3 | 覆盖 3 次判断失误 |
| L5 重来 | 「重新开始」同 seed | 允许「复盘」 |
| L6 泄压 | 星级不因失败扣减，只记录最佳 | 降低重复挑战的心理成本 |

### 7.4 「无解」的另一种解释：玩家把自己走死

这是需要正面承认的：**生成器保证有解，但玩家可能走进一个"从当前槽位状态已无解"的局面。**

例如：槽位躺着 A、B、C、D、E（5 种各 1 张），剩下 2 格。此时无论点什么都必然溢出。

**这不是 bug，这是游戏。** 处理方式：
1. 槽位 5 种不同元素时，底部给出**柔性提示**（不打断）：「差一点点就满了，试试先把槽里的牌配上」；
2. `hint` 道具（L4 起）会从当前状态重跑 DFS，**若判定当前状态已无解，hint 会直接告诉你「这里已经救不回来了，撤销吧」**——这比给一个错误的"下一步"诚实得多；
3. 这是 `undo` 存在的根本原因。

### 7.5 性能边界

| 项 | 上界 | 说明 |
|---|---|---|
| 盘面 DOM 节点 | 45 张牌 × 2 层（cell + face）= **90 节点** | 无压力，且**零 `<img>`** |
| 盘面图片请求 | **0** | 瓦片是纯 CSS 绘制（§8.1.1）→ 无加载抖动，首屏最快 |
| 弹层图片 | 按需 1–21 张 | 只在打开 S-03/S-04/S-06 时加载 |
| 遮挡重算 | 每次点击 ≤ 4 次比较 | 增量，非全量 |
| 生成耗时 | < 50ms | 实测平均 1.0–1.1 次尝试即通过 |
| 动画 | 全部 CSS transition/animation，**零 `filter`** | 无 `requestAnimationFrame`、无 canvas；遮挡态只改 background/border/shadow，走合成器 |
| layer 层叠 | `.sg-board { isolation: isolate }` | 隔离后瓦片 z-index 与页面 `.navbar`(100) / 模态框(500+) 互不干扰 |

#### 8.1.1 ⛔ 盘面瓦片不用 PNG，用纯 CSS 绘制（art-director 已否决 PNG 方案）

**结论：盘面瓦片 = CSS 绘制（族色填充 + 符号 + 分类色本身即填充色）；PNG 只用于 S-03 / S-04 / S-06 三个弹层。**

否决理由（基于对 118 张 PNG 的实际检查）：

1. **比例不符**：118 张全是 **800×1000 竖版卡（比例 0.800），且背景为不透明深藏青（约 `#1e2540`），不是透明底**。`object-fit: cover` 进方形瓦片会裁掉上下各 100px——**顶部族色条与底部族名全部被裁掉**；`contain` 则左右留藏青边，浪费 20% 宽度。
2. **反而丢失分类色可读性**：图里族色只出现在顶条、序号、底部族名三处，在 55px 下三处全部不可读。而分类色是**同族三消的核心信号**，这等于用 PNG 换来了信息损失。
3. **同质化**：118 张共用同一个深藏青底，55px 下整盘就是一片相同的深色方块 + 一个小白字——正是用户最初抱怨的"所有瓦片长得一模一样"，只是从白色换成了藏青。

> 这三条合并起来是一个反直觉的结论：**用真实资产图反而比纯 CSS 绘制更单调、更不可读。** 800×1000 的卡是为"放大看信息"设计的，放进弹层正好物尽其用。

**额外收益**：盘面零图片请求 → 首屏更快，不存在图片加载抖动（原先 R8 风险自动消失）。


| 属性 | 取值 | 谁产出 | 用途 |
|---|---|---|---|
| `--gx` / `--gy` | 半牌单位整数 | 关卡配置 | 纯 CSS 定位（`left = gx × tile/2`） |

## 附录 A · 数值验证方法与实测数据

本 GDD 的所有几何与难度数值**不是估计，是用一次性 Node 脚本跑出来的**（脚本不进仓库，仅用于设计验证）。方法与结果留档，便于 engineering-lead 复现与 quality-lead 复核。

### A.1 几何与遮挡模型验证

```
模型：gx/gy 用半牌边长为单位；covers(A,B) ⟺ A.layer>B.layer ∧ |Δgx|<2 ∧ |Δgy|<2
验证内容：各候选形状的牌数、是否被 3 整除、起始可点比例、盘面尺寸
```

关键结论：

| 形状 | 牌数 | 层数 | 可点比例 |
|---|---|---|---|
| `rows[1,2,3] + [1,2]`（三角） | 9 | 2 | 33% |
| `3 层 × rows[3,3]` | 18 | 3 | 33% |
| `3 层 × rows[4,4]` | 24 | 3 | 33% |
| `3 层 × rows[5,5]` | 30 | 3 | 33% |
| `3 层 × rows[4,4,4]` | 36 | 3 | 33% |
| `3 层 × rows[5,5,5]` | 45 | 3 | 33% |
| ~~`rows[1,2,3,2,1] + [1,2,3,2] + [1,2]`（菱形）~~ | 20 | 3 | **17%** ← 太闷，否决 |

> **解析结论**：当所有层同形且 `off` 逐层 +1 时，起始可点比例**恰好等于 1/层数**。这是一个可以直接用来规划关卡的闭式结果。

### A.2 三种生成方案的对照实验

| 方案 | 描述 | 有解率 | 拟人 AI 胜率 | 随机乱点胜率 | 结论 |
|---|---|---|---|---|---|
| A 纯随机 | 均匀发牌 | 取决于牌数，大量无解 | — | — | ❌ |
| B 按移除序分块 | 移除序切块，块内分整组 | **100%** | **100%** | **100%** | ❌ 过于简单 |
| C 随机 + 有界 DFS 验证 + 重掷 | 本 GDD 采用 | **100%**（采纳即已证明） | 20–100%（随 `nd`） | 0–87% | ✅ |

**方案 B 的失败值得单独记录**：它保证了「三张同元素的牌在移除序里彼此邻近」，这等价于向玩家泄露了答案。实测中，**连完全随机乱点的 AI 都以 100% 通关**——这证明该方案生产的不是谜题，而是自动播放。

## 附录 C · 交给 engineering-lead 的 6 条实现提示

1. **遮挡用整数判据，不要用 `getBoundingClientRect()`。** `covers(A,B) ⟺ A.layer>B.layer && |Δgx|<2 && |Δgy|<2`（`gx/gy` 以半牌边长为单位）。整数比较让遮挡图能在**渲染之前**算出来——这是生成器能工作的前提。
2. **`pointer-events` 不是遮挡的实现手段，是动画锁的实现手段。** 被遮挡的牌必须保持可点击，靠"点中后就抖动 + 高亮压住它的牌"来反馈。`pointer-events:none` 只用在三处：飞出动画中的牌、教学强制点击时的非目标区域、结算遮罩。详见 §3.3。
3. **先消除，后判负。** `place → while(消除) → if(slot.length>=7) 失败`。顺序颠倒会让"第 7 张恰好凑成三消"被误判。同时消除必须用 `while` 而非 `if`（现版 `checkMatches` 的 `return` 是 bug）。
4. **生成器是「随机发牌 + 8000 节点 DFS 验证 + 失败重掷」，不是「按序分块」。** 分块方案已被实验否决（随机 AI 都 100% 通关）。DFS 顺带产出的 `witnessPath` 就是提示道具的数据源；但提示必须**从当前状态重跑**，不能读初始路径。
5. **删掉旧文件里的内联 `const elements` 数组。** `<script src="../../elements-zh.js">` 会声明全局 `elements`，重复声明会直接抛错白屏。**旧内联数组还有一个额外问题：它只有 `symbol/name/atomicNumber/group/period/info`，没有 `category`**，而视觉与匹配都要用 `category`——这也是必须切到全局数据源的原因之一。
   关卡加载时必须断言以下六项（任一失败即抛错，不要静默降级）：

   | # | 断言 | 失败后果 |
   |---|---|---|
   | A1 | `Σ(每层牌数) % 3 === 0` | 盘面永远消不完 |
   | A2 | `nd ≤ 牌数 / 3` | 有元素不足 3 张 |
   | A3 | 所有 symbol 的 `atomicNumber ≤ 103` | CJK 扩展区字形渲染成豆腐块（§5.4） |
   | A4 | `boardH ≤ 6`（tile 行） | 手机首屏放不下（§4.6） |
   | A5 | 元素池青绿带族数 ≤ 1、不同时含 `nonmetal` + `metal-p`，**且同族 distinct symbol ≤ 4、`metal-d` ≤ 3** | **盘面填充色/明度档不可读**（瓦片填充即分类色，§8.1.1 + §5.8） |
   | **A6** | **任一白名单族的成员数 ≠ 3** | **关卡退化成 90–100% 胜率（§5.9）** |

   另：每个 symbol 必须在 `elements` 数据表中能查到，缺一即抛错。

   > **A6 是最容易被忽略的一条**：它不报错、不崩溃，只是让关卡悄悄变得毫无难度（胜率 100%）。请在开发期把 6 个关卡的"每族成员数"打印到 console 核对一遍。这也是本轮修订发现的最大设计漏洞，见 §5.9。

6. **`data-tier` 必须是 `symbol` 的纯函数，且与匹配通路彻底分开。** `tier = f(symbol)`——该关同族符号按 Z 升序取 0..3，**同一符号的所有副本共享同一档**（同元素三消靠"两张牌长得完全一样"配对，逐副本随机会让游戏直接坏掉）。`data-fam` 填**视觉亚族**（`metal-d/f/p` + 6 个原始族，共 9 值）只供 CSS 取色，匹配判定只读原始 `category` 并整体排除 `metal`——两条通路合并即触发主导策略（R13）。验收：对每关盘面按 `symbol` 分组，断言每组内 `data-tier` 集合大小为 1。完整 DOM 契约见 §8.1。
